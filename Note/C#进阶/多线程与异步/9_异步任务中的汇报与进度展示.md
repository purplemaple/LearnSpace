
在一个 WPF 程序中，我们在界面上放了一个进度条（ProgressBar），从而展示当前任务的进度。那么该如何汇报异步任务的进度呢？

## 1 使用Dispatcher

```xml
<StackPanel Margin="20, 0"
            VerticalAlignment="Center">
    <Button Name="button"
            Width="100"
            Margin="0,0,0,10"
            Content="Run"
            Click="Button_Click" />
    <ProgressBar Height="20"
                 d:Value="10"
                 Name="progressBar" />
</StackPanel>
```
MainWindow.xaml.cs中的逻辑：
```cs
public partial class MainWindow : Window
{
    public MainWindow()
    {
        InitializeComponent();
    }

    private async void Button_Click(object sender, RoutedEventArgs e)
    {
        try
        {
            button.IsEnabled = false;
            await DoJobAsync();
            button.IsEnabled = true;
        }
        catch (Exception){}
    }

    async Task DoJobAsync()
    {
        for (int i = 1; i <= 100; i++)
        {
	        //1.0 false表示模拟后续操作由非UI线程完成的情况
            await Task.Delay(50).ConfigureAwait(false);
            //1.1 非UI线程直接使用UI资源时会出异常
            //progressBar.Value = i;
            //1.2 使用Dispatcher在UI线程上操作UI资源     
            Dispatcher.Invoke(() => progressBar.Value = i); 
        }
    }
}
```

**Dispatcher（或Application.Current.Dispatcher）老套且不够优雅**

## 2 使用Progress 类

修改DoJobAsync方法：
```cs
async Task DoJobAsync(IProgress<double> progress)
{
    for (int i = 1; i <= 100; i++)
    {
        await Task.Delay(50).ConfigureAwait(false);
        progress.Report(i);
    }
}
```
其中 *progress* 参数来源于：
```cs
private async void Button_Click(object sender, RoutedEventArgs e)
{
    try
    {
        button.IsEnabled = false;
        Progress<double> progress = new(value => progressBar.Value = value);
        await DoJobAsync(progress);
        button.IsEnabled = true;
    }
    catch (Exception){}
}
```
由此，我们只需要在使用时实例化一个 `Progress<T>` 对象即可，它还可以传入一个回调函数，在每次 `Report()` 时执行，例子中的逻辑很简单，负责将传入的 `double` 类型数字赋值给进度条的 `Value` 属性即可

**那么，`Progress` 是如何规避线程问题的呢？观察`Progress`源码可以发现：**
```cs
public Progress()
{
    // Capture the current synchronization context.
    // If there is no current context, we use a default instance targeting the ThreadPool.
    _synchronizationContext = SynchronizationContext.Current ?? ProgressStatics.DefaultContext;
    Debug.Assert(_synchronizationContext != null);
    _invokeHandlers = new SendOrPostCallback(InvokeHandlers);
}
```
在它的构造函数中，拥有一个 `SynchronizationContext` 对象，它持有了当前的同步上下文`SynchronizationContext`。当我们在 `Button_Click` 方法中声明它时，还在 UI 线程，因此它就保存了这个上下文。然后在其 `Report` 方法被调用时，就会在正确的同步上下文（也就是 UI 线程）中执行相关逻辑了。

> Info
> 除了给构造函数传回调，`Progress` 类还为我们提供了一个 `ProgressChanged` 事件。注册这个事件可以实现相同的效果，并且也是在相同的同步上下文执行的。

### 自定义Progress

如果我们还有其他额外的需求，那么我们还可以自己实现`IProgress`接口，或者继承 `Progress` 类。官方特意没有将这个类设为 `sealed`，并且将 `OnReport` 方法设为 `virtual`，就是为了满足我们的这些需求。

> Info
> 但是如果我们去继承这个 `Progress` 类，会发现其实我们能自由发挥的空间并不大，因为它其中的很多字段（尤其是同步上下文）都是 `private` 的，所以我们能做的事情基本上也只有重写 `OnReport` 方法了。

自定义子类：多了`complete`表示在进度完成后执行的回调方法，和`maximum`表示最大进度(用于检测是否已经完成)
```cs
class MyProgress<T> : Progress<T> where T : notnull
{
    private readonly Action? _complete;
    private readonly T _maximum;
    private bool _isCompleted;

    /// <summary>
    /// 自定义 Progress 的构造
    /// </summary>
    /// <param name="handler">每次 Report 时的回调</param>
    /// <param name="complete">这里指进度条走完后执行的回调</param>
    /// <param name="maximum">进度条最大值</param>
    public MyProgress(Action<T> handler, Action? complete, T maximum): base(handler)
    {
        _complete = complete;
        _maximum = maximum;
        //注册委托
        ProgressChanged += CheckCompletion;
    }

    protected override void OnReport(T value)
    {
	    //如果进度条已走完则汇报
        if (_isCompleted)
            return;
        base.OnReport(value);
    }

    //用于检测当前进度条是否已经走完
    private void CheckCompletion(object? sender, T e)
    {
        if (e.Equals(_maximum) && !_isCompleted)
        {
            _isCompleted = true;
            _complete?.Invoke();
        }
    }
}
```
然后就可以这样使用：
```cs
private async void Button_Click(object sender, RoutedEventArgs e)
{
    try
    {
        button.IsEnabled = false;
        //2.1 创建自定义 Progress 类对象并传入进度条完成时的回调
        MyProgress<double> myProgress = new(
            _ => progressBar.Value += 1, 
            () => progressBar.Visibility = Visibility.Hidden, 
            100);
        await DoJobAsync(myProgress);
        button.IsEnabled = true;
    }
    catch (Exception){}
}
```
这里实现的效果是，当异步任务完成后，将会隐藏进度条。

### *延申：在传统多线程环境中使用*

不使用`await DoJobAsync(myProgress)`而使用`Parallel`
1. .Net 8.0 以下
```cs
private async void Button_Click(object sender, RoutedEventArgs e)
{
    try
    {
        button.IsEnabled = false;
        //在传统多线程中使用
        await Task.Run(() => Parallel.For(1, 100, value =>
        {
	        //注：Random.Shared 从 .Net 6.0 引进，是一个线程安全的 Random 实例
            Thread.Sleep(Random.Shared.Next(500));
            ((IProgress<double>)myProgress).Report(value);
        }));
        
        button.IsEnabled = true;
    }
    catch (Exception){}
}
```
2. .Net 8.0 及以上
```cs
private async void Button_Click(object sender, RoutedEventArgs e)
{
    try
    {
        button.IsEnabled = false;
        //使用.Net 8.0 新增的 ForAsync
		await Parallel.ForAsync(1, 100, async (value, _) =>
		{
		    //注：Random.Shared 从 .Net 6.0 引进，是一个线程安全的 Random 实例
		    Thread.Sleep(Random.Shared.Next(500));
		    ((IProgress<double>)myProgress).Report(value);
		});
        
        button.IsEnabled = true;
    }
    catch (Exception){}
}
```

### Progress总结

使用标准库中的`IProgress`接口及其实现类`Progress`即可实现异步任务的汇报与进度展示。
原理是：**实例化 `Progress` 时会自动获取当前线程的同步上下文（`SynchronizationContext`），汇报（`Report()`）时会由该上下文执行。**
因此，在某个线程实例化该类时，即可保证将会由这个线程来执行回调（汇报）

## 3 使用`IAsyncEnumerable<T>`+`await foreach`异步流

**技术框架**

1. `IAsyncEnumerable<T>` ：真异步流，不阻塞UI
2. `await foreach`（异步流消费）
3. `yield return`（异步产出：自然地逐步产出数据，无需事件)

View：
```xml
<StackPanel Margin="20, 0"
            VerticalAlignment="Center">
    <Button Name="button"
            Width="100"
            Margin="0,0,0,10"
            Content="Run"
            Command="{Binding StartWorkCommand}" />
    <ProgressBar Height="20"
                 d:Value="10"
                 Value="{Binding ProgressValue}"
                 Maximum="{Binding ProgressMaximum}"/>

    <TextBlock Margin="5"
               Width="200"
               FontSize="16"
               Text="{Binding ProgressText}" />
</StackPanel>
```

ViewModel:
```cs
internal partial class MainViewModel : ObservableObject
{
    [ObservableProperty]
    int progressValue = 0;

    [ObservableProperty]
    int progressMaximum = 100;

    [ObservableProperty]
    string? progressText;

    public MainViewModel() { }

    [RelayCommand]
    public async Task StartWork()
    {
	    //异步枚举语法，会在每次 yield return 时收到一个进度
        await foreach (var progress in DoJobAsync())
        {
            ProgressValue = progress;
        }
    }

    async IAsyncEnumerable<int> DoJobAsync()
    {
        for (int i = 1; i <= ProgressMaximum; i++)
        {
            await Task.Delay(50);
            //每次遇到 yield return 时，都会将当前的值返回给调用方（上层消费者），并暂停方法的执行状态，直到下一次请求下一个值时才继续执行
            yield return i;
        }
    }
}
```

### 如果需要汇报更复杂的信息：

自定义 `record`
```cs
record ProgressInfo(int Step, string Message);
```

修改`DoJobAsync`方法：
```cs
async IAsyncEnumerable<ProgressInfo> DoJobWithInfoAsync()
{
    for (int i = 1; i <= ProgressMaximum; i++)
    {
        await Task.Delay(50);
        //每次遇到 yield return 时，都会将当前的值返回给调用方（上层消费者），并暂停方法的执行状态，直到下一次请求下一个值时才继续执行
        yield return new ProgressInfo(i, $"当前进度：{i}/{ProgressMaximum}");
    }
}
```

修改消费端：
```cs
[RelayCommand]
public async Task StartWork()
{
    //异步枚举语法，会在每次 yield return 时收到一个进度
    await foreach (ProgressInfo info in DoJobWithInfoAsync())
    {
        ProgressValue = info.Step;
        ProgressText = info.Message;
    }
}
```

### 异步流原理：

你的 `yield return`：
```cs
public async IAsyncEnumerable<int> CountAsync() 
{     
	for (int i = 1; i <= 5; i++)     
	{         
		await Task.Delay(50);         
		yield return i;     
	} 
}
```

编译器会生成一个隐藏的异步状态机类，类似：
```cs
class CountAsyncStateMachine : IAsyncEnumerable<int>, IAsyncEnumerator<int>
{
    public ValueTask<bool> MoveNextAsync() { ... }
    public int Current { get; private set; }
}
```

你的 `await foreach`：
```cs
await foreach (var item in GetValuesAsync()) { }
```

编译器会把它翻译成：
```cs
await using var enumerator = GetValuesAsync().GetAsyncEnumerator();  
while (await enumerator.MoveNextAsync()) 
{     
	var item = enumerator.Current;     // loop body 
}
```

运行机制：
1. 用户第一次执行 `await foreach` → 调用 MoveNextAsync
2. MoveNextAsync 执行用户方法
3. 遇到 await → 挂起
4. await 完成 → 恢复 MoveNextAsync
5. 遇到 yield return → 返回一个值 → MoveNextAsync 完成
6. await foreach 循环体触发
7. 下一次 MoveNextAsync 重复所有步骤
8. 方法结束 → MoveNextAsync 返回 false


简化流程图：
```cs
┌─────────────┐    yield return 1 ...  ┌──────────────┐
│  DoJobAsync │ ─────────────────────▶ │   StartWork  │
└─────────────┘                        └──────┬───────┘
       ▲                                      │
       │  foreach 再请求下一个                  │ foreach 再请求下一个
       │                                      ▼
┌─────────────┐    yield return 2 ... ┌──────────────┐
│  StartWork  │ ◀──────────────────── │  DoJobAsync  │ 
└─────────────┘                       └──────────────┘

```

### 异步流总结

>`IAsyncEnumerable<T>` 是一个异步序列接口，`MoveNextAsync` 返回一个 `ValueTask<bool>`
> `await foreach` 是编译器语法糖，它把循环展开为异步获取元素；  
> `async` + `yield return` 会自动生成一个异步状态机，用 `MoveNextAsync` 控制推进；
> 每次遇到 `yield return` 时，`MoveNextAsync` 返回结果并自身迭代到下一个
> 下一次 `await foreach` 进来时重复所有步骤
> 因此可以一边 await 异步操作，一边 yield return 数据，形成异步流。
